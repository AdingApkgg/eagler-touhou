搬迁前已检查 14 个来源分支及 12 个实际检出目录，提交已授权的工作并推送，全部选定来源与远端同步且工作区干净。确切来源见 [来源记录](move-sources-20261018.json)。原仓库及历史保留。

## 明确失败与剩余范围

停止本任务 Runtime C++ 编译并结束前端构建测试后，在刷新后的 TH08 MP 生产 WASM 上独立重跑：

- `packets`：第 185 帧、座位 0 的输入捕获被拒绝。
- `relay`：确认输入停止推进，`next=42`、`confirmed=33`。

两项均与搬迁前的失败形态一致。尚未定位驱动与产品行为的责任边界，不能据此宣布产品根因。没有降低行为断言、改变游戏算法或恢复逐作 common 固定版本来消除失败。

随后在未搬迁的原 TH08 MP 仓库 `ed28bff70dd7075d028944869b4b8083aff52db8`、其原锁定 common `44d0732e0f3569dc107512fefa0ef5c535c01925` 和原 Launcher main `d0c136487442e0648bb24aa903e37a32461ce358` 上重新构建复验。522 项构建输入与实际浏览器 WASM 身份一致，原测试入口未修改，三处源码工作区保持干净。数据包用例仍在输入捕获断言失败，两座位下一捕获帧均为 185，双方 net、driver、native、canonical 数组与候选失败状态逐项相同；原 Relay 同样停在 `next=42 / confirmed=33`。这证明两种失败早于此次目录和服务迁移。

用户在获知上述原仓库对照结果后明确表示“可以不管这个”。因此这两项既有失败不再阻断本次源码发布，测试仍记为失败，不据此声称实际联机缺陷已经定位或修复。

本轮实际游戏入口为 `launcher/tests/browser/test-local-replay-native.py` 和 `ports/th08-mp/portable/multiplayer/check-network.mjs`。专用 MP 录像录制及旧性能冻结脚本仍有原工作区/分支假设，需要按入口继续适配和独立验收；本次不宣称所有历史诊断命令都已迁移通过。

其余作品/MP 的完整游戏行为、原版确定性、真人与设备、公网代理地址归属和配额隔离均不在已通过范围。没有启用服务或改变公网端口。远程 CI、公开 fork/PR 和 linked worktree/SDL 协作也未作为本轮已执行证据。
