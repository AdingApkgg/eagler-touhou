# Restart 背景与过渡动画修复

用户截图中的紫色图案来自原版 effect.anm 内嵌的 effect/eff_switchbg.png，不需要额外制作贴图。

## 两处根因

1. 原版叠加效果按画面像素格式启用目标透明通道遮罩，并绘制第五块图案面板。原版 0x40b0b0 读取 0x4e78cc，值 21 对应 32 位带 Alpha 的画面格式。旧的 AnmEnvironment 将此条件误命名为 continue_prompt，游戏启动时没有赋值，因而始终跳过紫色背景。现在字段为 render_target_has_alpha，由 SDL 实际屏幕格式初始化。
2. 原版创建重开效果时，经 0x4229c0 / 0x423020 注册为 ordering=4 的叠加动画。旧平台入口用普通动画组，Restart 等待期间游戏更新中断，使效果面板也停止更新。现在使用 create_overlay，背景会按原版效果脚本正常打开并回到关卡。

修改位于 cpp/game/AnmEnvironment.hpp、cpp/game/AnmOverlayRenderer.cpp、cpp/sdl/Application.cpp 和 cpp/sdl/ApplicationGame.cpp。核心测试 setter 保留旧导出名以兼容原有测试接口；生产代码使用正确的画面格式语义。共用 SDL3/WebGL2 Renderer 没有修改，也没有引入 Windows 图形 API。

## 验证

- 同一份旧开发 Wasm、相同 Easy/灵梦/无欠模式输入重现灰色背景，旧版阴性对照单独保存。
- 实际自机死亡、原版游戏结束菜单 Continue、章节恢复：640×480 与 1280×960 均检查重开首帧、第 15/30/50 帧和恢复游玩后的 GPU 画面。
- 最终生产启动器用真实键盘输入选择无欠模式，再经暂停菜单 Retry 和确认：无开发探针，实际画面显示紫色图案，随后恢复关卡。截图为 production-restart-overlay.png 和 production-restart-resumed.png。
- 实际 IndexedDB 存档、页面/Wasm 冷启动及继续游玩检查通过。
- 原版动画面板、章节恢复顺序，以及已有早苗 Extra 40,860 帧、铃仙六面 123,606 个有效帧对照重新通过。核心 Wasm 二进制指纹仍为 03d67dd0a7eafed3640520f2c8c95f0bc51b55998e4ec1b5fe2d6300d31d34df。
- 桌面/模拟手机 DPR2 的生产标题合成、115 个发布文件完整性、当前源码与测试/生产构建一致性检查通过。

检查只覆盖上述样本与路径，未声称对所有输入和所有手机驱动作穷尽像素证明。
