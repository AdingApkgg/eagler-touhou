# 启动器结构与职责

启动器负责作品选择、游戏包、浏览器存储和页面导航。Runtime 运行游戏逻辑。所有作品共用 `launcher/` 中的前端和 Host。

## 源码归属

| 目录 | 职责 |
| --- | --- |
| `launcher/app/`、`launcher/src/` | React 页面、路由和浏览器逻辑 |
| `common/contracts/` | 前端与服务共用的产品和协议定义 |
| `launcher/src/contracts/` | 上述定义的 TypeScript 接口 |
| `launcher/package/` | 游戏包导入、存储、更新与 ZIP 处理 |
| `launcher/host/` | 按输入装配可部署的站点 |
| `launcher/integrations/` | 字体、汉化及外部资源格式 |
| `launcher/server/`、`launcher/scripts/serve.mjs` | 本地 HTTP 与 THCRAP 服务 |
| `launcher/lib/` | Node 构建、策略和产物模块 |
| `launcher/scripts/` | 命令行入口 |
| `launcher/public/` | 浏览器静态资源 |
| `ports/<owner>/` | 各作游戏源码及 Runtime 构建、打包 |
| `common/` | 各作共用运行库 |
| `tools/`、`.github/workflows/` | 全仓构建工具与 CI |

表中路径均从仓库根目录定位。

[`workspace.json`](../config/workspace.json) 映射源码目录；[`runtime-builds.json`](../config/runtime-builds.json) 声明构建模式和命令。TH06、TH07、TH09 的普通版与 MP 共用各自源码目录；TH08、TH10、TH11、TH15 的两种模式分目录维护。TH20 提供普通版。

## 从源码到运行

1. `build:runtime` 按配方编译游戏，记录源码与构建信息。
2. 该作打包脚本收集 HTML、JavaScript、WASM 和 Runtime 资源。
3. 前端选择游戏包，准备 DATA、语言和音乐组件。
4. Host 提供页面和 Runtime；浏览器会话加载所选作品。
5. 存档与 Replay 写入浏览器的可变存储，随游戏包更新继续保留。

批量发布 Runtime 使用 `scripts/package-runtime-release.mjs`；装配部署站点使用 `host/build.mjs`。本地开发需要前端构建、所选 Runtime 和本地游戏包，作品由 `EAGLER_DEVELOPMENT_GAMES` 选择。

## 房间预加载与设置

进入房间后先准备资源，再调用声明 `roomPreview: true` 的 Runtime 的 `prepare-room`。就绪标记要求原生标题已经显示；标题保持动画，忽略输入并禁止自动演示。开始对局复用同一个实例，按双方确认的种子和配置重置对局状态。

需要重新加载的设置先保留为草稿，不卸载当前标题。游戏区域右上角浮层提供“重载资源”和“返回原有设置”；只有确认重载才替换 Runtime。设置抽屉返回按钮只关闭抽屉，不能触发重载。

关闭回滚时显示输入延迟与“自动实测”；自动实测禁用手动调整，手动模式保留所选帧数，包括零。TH15 从菜单返回战斗前排空菜单捕获队列，避免额外输入延迟。

多人 Replay 可从大厅直接进入共用播放器，不要求先开房。满员或游戏中的房间仍允许进入旁观席，实时画面由作品自身的旁观接口接入。

房间与 Replay Manager 共用画面尺寸适配：手机按内容宽度确定 4:3 画面高度，桌面保持播放器全宽、使用面板内的可用高度。画面区域的高度上限跟随宽度，避免上下留白占用空间，左右留白交由 Runtime 保持完整画面。窗口与设备方向变化时自动重新适配。观战席默认显示头像预览，点击图标、标题或头像打开完整名单并管理成员。预览栏保留加入／离开旁观按钮，手机布局将按钮置于右侧栏底部；预览与完整名单共用同一成员操作。

玩家卡片以与准备按钮同色的鲜红、参考图的青绿色区分未准备与已准备，加载时使用暖橙色。有人卡片采用无描边的纯色表面，头像环保留资源准备进度，就绪环为浅绿；头像内文字按圆环尺寸缩小留白。READY / UNREADY / LOADING 使用深色装饰字。状态切换时底色平滑过渡，字标逐字错峰滑入、自然收稳，旧字标同步淡出。减少动态效果设置下直接显示最终状态。

卡片头像列固定靠上，P1 / P2 / P3 位于对应头像上方；右侧文字组垂直居中、保持左对齐，按玩家名、自机和连接信息分层。名字与自机使用站点内置的 Chill Round 粗体，连接标签降低强调，延迟值使用等宽数字。底色、背景状态字的位置和逐字动画沿用现有呈现，前景自然覆盖装饰字。页签滑动指示条、内容切换、卡片进入、快捷发言与菜单展开采用短促过渡，按钮按下时给出即时反馈。

手机双人房和三人房统一将约 84px 高的卡片上下排列在左侧，保留头像在左、文字在右的内部结构，右侧以窄列预览观战头像，底部提供加入／离开旁观。旁观者为 1～2 人时，头像放大到 40px 并在窄列中单列居中；人数增加后采用紧凑头像网格并在栏内滚动。桌面按房间人数并排呈现玩家卡片。空席加入、长昵称省略和连接详情沿用同一套成员操作。

空席以完整的圆角虚线卡片呈现，整张卡片均可点击加入。玩家移到旁观席后，原席位恢复加入入口，头像预览标记本人，完整名单提供离开旁观入口；准备与开始操作收起，手机同步释放底部操作区。资源就绪提示区按入座状态显示准备、选择席位或已进入旁观席。

竖屏时，快捷发言按钮位于聊天页签下方，消息在按钮下方排列。快捷发言选项使用共用全屏浮层宿主，脱离聊天面板的滚动与裁切边界，按视口剩余空间向上或向下展开。展开与收起分别提供渐显缩放、淡出反馈；发送后回到触发按钮，Escape、方向键和点击外部均有明确操作。

成员卡片的更多菜单与快捷发言共用 `RoomActionMenu`：菜单表面、选项高度、焦点样式、视口定位及展开／收起动画保持一致。更多按钮在展开时旋转点阵，按下时缩放，危险操作单独标色。游戏设置将不可用的回滚／延迟行完整收起，标题直接衔接可用控件；规则说明使用简短的功能描述。

Replay Manager 桌面布局将返回按钮放在独立顶栏，录像列表与播放器面板顶部对齐。

共用播放器保留常驻 iframe，画面适配与面板内触控层边界集中在 `PlayerSurface`。房间成员、资源准备和 Replay 文件及播放控制由各自工作区组合。游戏与触控编辑器共用安全区几何：大尺寸控件临时缩放至当前安全区内，窗口恢复后按保存尺寸重新显示；保存布局保持用户设定。

房间使用持续加载的游戏实例。退出旁观先同步存档，再通过 `return-room` 结束本局网络接收并回到原生标题菜单；房间成员身份、旁观席、iframe、程序和 DATA 保持加载，再次观战复用同一实例。房间内的游戏检查也直接使用已经准备的实例。离开房间、确认资源重载或更换 Runtime 身份时释放相应实例。

支持保留实例的 Runtime 在 `ready` 声明 `roomReturn`，每次 `launch` 和对应的 `first-frame` 携带 `launchSerial`，使重复进入时的首帧只解除本次启动遮罩。房间菜单返回由各作原生场景管理器完成，网络、回滚及临时输入按本局边界清理。

联机准备按完整程序版本校验；准备按钮重新检查服务器当前版本，玩家版本一致后才允许开局。晚加入的旁观者还要与正在运行的对局版本一致；服务器发布新版后，版本不同的旁观者会收到等待下一局或全员重新准备的提示。已经运行的对局继续使用其固定版本。游戏包和程序更新都在下载、校验完成后提供使用入口，更新确认会等待对局和其他弹窗空闲。

连接、重连和开局标定进度位于播放器右上角，窗口限制在当前视口内并支持滚动。更新确认、资源导入、启动错误详情和标定报告使用页面顶层弹窗；全屏时仍可操作。共用提示宿主统一承载资源导入、下载链接和错误详情，层级高于房间、Replay 工作区及设置抽屉；窗口关闭后，空白区域直接响应底层操作。缺少必需资源时，玩家在房间内完成导入，随后自动继续房间准备。房间中的个人设置、连接详情和旁观名单使用共用的居中房间面板。

## 命令入口

| 命令（从 `launcher/` 运行） | 结果 |
| --- | --- |
| `npm run dev` | 启动带热更新的 React 开发服务器 |
| `npm run build` | 准备锁定版本的浏览器库，构建内容页面、客户端模块和 React 产物 |
| `npm run typecheck`、`npm test` | 检查前端类型与行为 |
| `npm run check` | 检查启动器核心模块 |
| `npm run check:workspace` | 检查跨作品 Runtime 集成 |

具体输入和步骤见[本地联调](DEVELOPMENT.md)与[测试入口](../tests/README.md)。脚本职责见[命令目录](../scripts/README.md)。
