### 4. 语义 Draw 与可废弃的 GPU 写入分开

新增 Renderer 宿主命令带及 `RasterLiveness.hpp`，不跳过任何 Update、ANM/Stage 语义 Draw 或封帧。只在提交 GPU 前逆序检查已生成的命令：

- 每个最终颜色、深度、模板资源起初都要求保留全部像素。
- 只有真实 clear 可以移除被完全覆盖的像素需求；普通 draw 不被假设为不透明覆盖。
- 仍被需要的 draw 会保留其纹理源与深度依赖；纹理采样保守要求完整源图。
- 局部 clear 只减去其整数区域，外部像素继续保留。矩形分裂/资源容量溢出保守保留，不能误删。
- 只丢弃既不影响最终资源、也不被后续有效绘制读取的 GPU 写入；调用过的语义 Draw 已经完整运行。
- GPU 读回、拷贝、重采样、CPU 纹理写入、释放、ImGui、世界 Restore 等都先完成 raster fence。
- 不完整纠正仍不 Present。GPU 命令可跨恢复让出保留，但不是让半恢复世界上屏。

命令、几何、矩形均有上限，满载后按原顺序保守提交。保留实际绘制数量与另列的省略统计，不能把省略量计为 FPS。

### 5. 最后一个历史 tick 的有限完成机会

### 开局失败定位与测试 FIFO 修正

`20261014b-r20-relay35-pure` 在开局前失败：`Invalid peer packet`，逻辑帧 0、恢复次数 0、raster 统计全 0。两端初始游戏 hash 一致。

原始 transport 签名记录显示，P2 先发送 32-byte `525062039`，后发送 `784798308`；P1 却先收到后者，再收到前者。结合 `SessionChannel::SendSession` 的 Hello→Ready 顺序及 `ReadyBeforeHello` 的严格失败分支，定位到 relay 逐包抖动计时器打乱握手顺序，而非放宽 native 握手校验可以解决的问题。

**这也意味着修正前的带抖动 relay 结果是额外乱序压力，不能当作忠实 TCP 顺序基线。** 原失败与全部慢场均保留，不事后重写为有效稳定网络测试。

最终测试 shim 保留原 timer 和字节，但已到时的后包必须等待之前安排的包到时或取消后才能交付。该 FIFO 为全局队列，强于单连接 TCP 顺序，会耦合不同 socket，因此在 receipt 中明确记录为测试限制，并分别保存 timerFired / fired / FIFO hold。没有修改正式 relay、common、游戏包或 ReadyBeforeHello 校验。

新增真实 `createBoundedRelaySender` 单测主动先触发 READY 定时器，确认零提前交付，然后触发 HELLO，得到原字节 HELLO→READY；另保留原 timer、取消与无关计时器测试。两项测试均通过。启动期额外保留原始小包字节以便后续定位。
