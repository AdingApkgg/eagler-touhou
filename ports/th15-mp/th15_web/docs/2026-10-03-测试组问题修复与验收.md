## 画面分辨率

正式启动器根据画布显示宽度与设备像素比，在启动时选择 640×480 或 1280×960。可在网站 URL 追加 `?renderScale=2` 强制 1280×960；`?renderScale=1` 使用原倍率。需要退出并重新启动游戏才应用。倍率不会更改移动、碰撞、弹幕出界、录像或游戏时钟。

## 录像对照说明

普通录像为项目中提供的 `th15_ud0186.rpy`，覆盖六面，SHA-256 为 `480e93f57235a8f4ceef9e1a3182d6e98bf4307c1390e7d872829d00d5886c76`。Extra 未收到测试组实际失败的 rpy；本轮使用相同格式的魔理沙射击/低速诊断输入，在原版和 C++ 中施加相同测试保护，覆盖 Extra Boss 各阶段。它证实了本轮发现的行为差异已消除，不代表所有角色、输入和录像都已证明一致。

原版进程记录只用于验收；正式浏览器模块没有测试保护、开发探针或原版指令执行器。原版与 C++ 检查玩家位置/状态、分数、死亡、残机、Bomb、Power、游戏 RNG 及敌人/弹幕数量。自然游玩、受控场景生命周期、软件 GPU 模拟触控和真实手机驱动是不同证据，不能混为“没有任何 Bug”。

## 测试组复测

1. 刷新网站，确认更新为本轮版本，保留现有存档。大屏/高像素比设备检查画面清晰度，也可用 renderScale=2。
2. 普通 Boss 和 Extra Boss 检查血条阶段线、狂暴线及长短符卡标题位置；打开排名、Replay、Player Data 检查字体。
3. 暂停确认声音，反复 Retry 与返回标题，重点观察之前半屏黑边的手机。
4. Extra Game Over 后连续 Retry，回标题再进 Extra；通关保存后不刷新直接读取同一录像。
5. Legacy 死亡后通关检查结局和 Clear/Stage 文案；保存首个新录像检查编号 01，名字编辑检查空格、退格、结束。
6. 用测试组实际失败的 Extra 录像复测；若仍偏离，保留该文件、原版版本及最早偏差时间。
