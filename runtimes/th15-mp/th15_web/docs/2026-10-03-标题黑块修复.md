# 标题黑块修复（2026-10-03）

本次是上轮场景清理改动引入的渲染回归，不是玩家操作或缓存资源损坏。

## 原因

`cpp/sdl/Application.cpp` 的 `release_run()` 为防止上一局残留绘图状态，新增了 `PipelineState{}` 重置。该结构默认关闭透明混合，透明比较也为 Always。程序初始化后进入标题同样经过此路径，覆盖了 GraphicsDevice 初始化时设置的正确游戏状态。

ANM 精灵会更新混合因子和颜色操作，但不会每张图片重新启用全局混合。因此透明像素被直接画到屏幕，出现人物、标题字、菜单周围的大块黑底。上轮只检查“画面有内容”和流程状态，没有对完整标题的透明合成作验收，错误地把该版本宣布为可用；旧版这些视觉验收不能证明显示正确。

## 修正

在清空绘图状态后重新执行 `graphics.configure_game(1)`，恢复原版需要的透明混合、透明阈值、深度比较及其他基准状态。保留先前血条、文字、录像、重开等修复及 1280×960 支持；共用 SDL3/WebGL2 后端没有更换。

正式 Wasm SHA-256：`b1cd3a312c00dcbf79e1a0c7c18c3247edf59f3437313b2eabcaa2c2a1b02d9a`。manifest version：`b234edcf4e1e6f44c9b51566`。

## 新增验收

- 实际应用在初始标题、进入一面、暂停退出后标题三个节点，分别在 640×480 与 1280×960 检查精灵的透明、半透明及不透明像素；测试不主动开启混合，只继承实际应用状态。期望值独立按背景与源像素的透明合成计算。
- 使用上轮实际 Application 编译对象构建隔离的故障对照，新测试失败：完全透明源像素仍覆盖背景，实际 BGRA 为 [40,80,120,0]，正确背景应为 [64,48,32,255]。修复版三个阶段和两个倍率均通过。
- 正式启动器桌面 1280×960 及模拟手机 DPR=2 的真实标题 Canvas 截图检查；不包含开发像素探针，确认大块黑色区域消失。截图比例检查只是黑块回归保护，不代表整幅原版逐像素等价。
- 正式包 115 个文件哈希与开发导出检查通过。游戏核心源码未改，本轮上一版的 324 项核心回归与录像状态证据继续适用于相同核心；此修正另有应用层/GPU视觉验收，没有以重复核心测试冒充视觉验证。
